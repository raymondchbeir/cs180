PART A / EXPLORING THE POWER OF FLOW MODELS

Working with a pretrained flow model

For this part i used PixNerd to test how flow matching works in practice, first by recovering images from noise and then using the same ideas to create new images, control them with prompts and build optical illusions.

1.1

Constructing noisy training inputs

I started by taking the same input image and mixing it with Gaussian noise at different values of t, i kept the noise fixed so the difference between the images comes from changing the time and not from getting a completely different random noise every time. When t is small there is more noise and when it gets closer to 1 we keep more of the original image, which is the idea we use again when we train our flow model in Part B.

xₜ = (1 − t)x₀ + tx₁where x₀ is Gaussian noise and x₁ is the clean image
1.2

Classical Gaussian denoising

First i tried Gaussian blur as a simple baseline, and for each noisy image i corrected the image amplitude and then blurred it with a Gaussian filter. This does remove some of the random high frequency noise but the issue is that we also blur edges and small details that actually belong to the original image, so it is useful as a comparison but it cannot really know the difference between noise and image structure.

1.3

One-step denoising

For this part i used the pretrained PixNerd flow model to predict the velocity at the noisy image and the current timestep, then i used that one velocity prediction to estimate where the clean image should be. It is a lot more informed than only applying Gaussian blur because the model has learned how images are structured, but one prediction is still an approximation since the correct velocity can change as we move toward the final image.

x̂₁ = xₜ + (1 − t)vθ(xₜ,t,c)
1.4

Visualizing the predicted velocity

Here i wanted to see what the model was actually adding to the noisy image, not only what the final picture looked like. Since i saved the original image and the exact noise used in the interpolation i could compute the ground truth velocity x₁ − x₀, then compare its update to the velocity predicted by the model. The error heatmaps show where those two updates disagree and help explain why a one-step result is not always identical to the original.

1.5

Iterative denoising with Euler sampling

Instead of making only one large jump to the end i implemented Euler sampling, so we predict the velocity, take a small step, and then predict another velocity using the updated image. I started from the noisy image at t = 0.5 and took 25 updates to reach t = 1, and the trajectory lets us see how the image changes during that process. The comparison puts Euler sampling next to Gaussian blur and the one-step result using the same starting image, which is important because otherwise we would not be comparing the methods fairly.

xₖ₊₁ = xₖ + Δt · vθ(xₖ,tₖ,c)
1.6

Generating images from pure noise

For image generation i used the same Euler sampler but this time i did not give it any original picture to recover, i started with random Gaussian noise at t = 0 and used the text prompt a high quality photo. I generated several samples with different random seeds, so the starting noise changes between images while the prompt and the generation method stay the same, and this is what makes it possible for the pretrained model to create a new image instead of just editing an image we already had.

2.1

Classifier-free guidance

I then added classifier-free guidance or CFG, the idea is to run the model twice at the same image and time, once with the actual prompt and once with an empty prompt, and then use the difference between their velocity predictions to push generation more toward what the text is asking for. I used a guidance weight of 7 and kept the initial random seeds the same as the earlier conditional samples so we can compare the effect of guidance itself. Stronger guidance can help with the prompt, but it can also reduce variety or create artifacts so more guidance is not always better.

vCFG = vuncond + w(vcond − vuncond)
3.1

Image-to-image editing

Now instead of starting from pure noise i started from an existing image, added different amounts of noise and let the model move it back toward a natural image. The interesting thing here is that the starting time controls how much freedom the model has, at low starting times the image has much less information left so the model can change it a lot, while at higher starting times it has much more of the original structure to follow. I tested the Campanile, my other input images, a web image and two drawings to see how the same method behaves with different kinds of inputs.

3.2

Text-guided image editing

In this experiment i kept the same image-to-image process but replaced the generic photo prompt with text describing what i wanted the new image to look like, this adds another way to control generation because now both the starting image and the text influence the output. The starting time is still important since at lower values the model has more room to follow the prompt and at higher values it tends to preserve more of the input. The exact prompts used for each experiment are written in the Part A notebook.

Before submitting: Add the exact prompt text for each of these three examples from your Part A notebook, as the assignment asks for the prompts to be shown with the images.

3.3

Visual anagrams

For the visual anagrams i used two prompts and tried to make a single generated image that works in two different orientations. At each Euler step i predict a velocity using the first prompt, then rotate the image by 180 degrees and predict another velocity with the second prompt, then rotate that second velocity back and average the two predictions. This means the two prompts both affect the generation process, and ideally the final image tells one story when it is upright and another story when it is upside down. I made two examples and included both the original results and the upright versus rotated views.

3.4

Hybrid images

Finally i generated hybrid images by combining two different velocity predictions, one prompt supplies the low frequency structure and the other supplies high frequency details. In each Euler step i apply a Gaussian low-pass filter to the two velocity estimates and keep the low frequencies from the first prediction and the high frequencies from the second. The idea is that when we look at the generated image up close we notice the fine details, while from farther away or when it is shown smaller the broad low frequency structure is easier to see. These are my two hybrid results, and i show each once large and once small so it is easier to compare those two views.

vhybrid = LP(va) + vb − LP(vb)
PART B / FLOW MATCHING FROM SCRATCH

Building and training my own model

For this part i moved from using a pretrained model to implementing the UNet in PyTorch and training it myself on MNIST, first as a one-step denoiser and then as a generative flow-matching model with time and class conditioning.

1.1

Building the UNet

For Part B i implemented the UNet blocks in PyTorch instead of using the pretrained model from Part A. The encoder has convolution and downsampling blocks so it can learn larger features, then the decoder upsamples those features back to the original 28 × 28 image size, and the skip connections let it reuse details from earlier layers. For the first denoising experiment i used D = 128 hidden channels and a single grayscale output channel, and the rest of this part uses the same main architecture with extra conditioning blocks added later.

MNIST28 × 28 grayscaleConv / Down / UpSkip connections
1.2

Adding Gaussian noise

Before training i took one MNIST test image and added Gaussian noise with standard deviations 0, 0.2, 0.4, 0.5, 0.6, 0.8, 1.0, and the figure makes it easier to see how the digit gets harder to recognize as the noise level increases. This is additive Gaussian noise, which is different from the interpolation used for flow matching later.

z = x + σεε is sampled from a standard Gaussian distribution
1.2.1

Training a one-step denoiser

I trained the UNet on MNIST for 5 epochs with a batch size of 256, Adam learning rate 1e-4, and noise standard deviation 0.5, and i generated a new noise sample every batch instead of reusing the exact same noisy dataset. The network tries to reconstruct the clean digit from the noisy input and MSE measures the error between the two. I saved the loss curve for the whole run and the test-set results after epochs 1 and 5, so we can see how it changes as training continues.

1.2.2

Out-of-distribution noise testing

After training only with σ = 0.5 i tested the same model on other noise levels without training it again, and i kept the underlying test digit the same so the main thing changing is the amount of noise. This lets us check whether a model trained for one amount of noise can still reconstruct the image when the input does not look like its normal training examples, and in general we expect it to have a harder time when the noise is much stronger than what it saw during training.

1.2.3

Trying to reconstruct a digit from pure noise

Then i trained a fresh UNet using completely independent Gaussian noise as the input and a clean MNIST image as the target, so unlike the denoising experiment there is no hidden digit inside the input that the network could recover. Since we use MSE, the best prediction when the input gives no information about the target is close to the average training image, which explains why this setup tends to produce blurred or mixed digit-like structures instead of one clear new digit. This is a good example of why simply asking for a full clean image in one step is not enough for generation.

2.1–2.2

Time-conditioned flow matching

For flow matching i changed the goal of the UNet, now it receives an intermediate image and a timestep and predicts the velocity that points from Gaussian noise toward a clean MNIST image. I added two FCBlocks that turn the scalar timestep into learned channel values and multiply those embeddings into the decoder features, this lets the network change its prediction depending on the current time. During training i sample independent noise x₀, clean images x₁ and a random t, then i construct xₜ and train with MSE against the target velocity x₁ − x₀.

I used D = 64, batch size 64, Adam with initial learning rate 1e-2 and an exponential scheduler with gamma = 0.1^(1/10) for 10 epochs.

xₜ = (1 − t)x₀ + tx₁   |   vtarget = x₁ − x₀
2.3

Sampling with the time-conditioned UNet

Once the UNet learns velocities i can start from pure Gaussian noise and use Euler steps to generate a new image, so for each step i ask the model for the current velocity and update the image by a small amount. I saved outputs from epochs 1, 5 and 10 to compare what the model could generate as it learned, and i also saved a separate final sampling result. The network is not told which digit to generate here, it only learns the overall MNIST distribution so the generated digit is not something i choose beforehand.

xₖ₊₁ = xₖ + Δt · vθ(xₖ,tₖ)
2.4–2.5

Class conditioning and training

Next i added class conditioning so i could ask the model to generate a specific MNIST digit instead of getting a random one, the digit label gets converted into a one-hot vector of length 10 and two extra FCBlocks convert it into channel features. I combine class and time information as c₁ × unflatten + t₁ and c₂ × up1 + t₂. During training i drop the class condition with probability 0.1, this teaches the same network how to predict a velocity both with and without the class and lets us use classifier-free guidance later.

I trained the class-conditioned model for 10 epochs with the same initial learning rate and scheduler used for the time-only experiment, and saved the loss curve and checkpoints at epochs 1, 5 and 10.

2.6

Class-conditioned sampling with CFG

For class-conditioned sampling i made four examples of each digit from 0 to 9, so each grid has 40 generated images. At every step i run the network with the real class condition and again with the class dropped, then combine the two velocity predictions using classifier-free guidance with scale 5.0. I used 300 Euler steps and kept the random seed fixed across the epoch checkpoints so we can compare the effect of training instead of getting completely different starting noise each time.

vguided = vuncond + 5(vcond − vuncond)
2.6 · extra comparison

Removing the learning rate scheduler

The assignment also asks if we can remove the exponential scheduler without losing too much performance, so i trained a second class-conditioned UNet from scratch but used a constant learning rate of 1e-3 for all 10 epochs. I picked a smaller rate instead of leaving it at 1e-2 because without decay the model would keep making relatively large updates even near the end of training, and the smaller constant rate is a simple way to make those updates more controlled. The tradeoff is that the model also gives up the larger updates at the start, so it may learn more slowly early in training, and the loss plot and final 40-image grid are what i use to compare the two runs. I do not assume removing the scheduler is equally good just because the code is simpler, the final samples and losses are the actual comparison.
